# 06 功能与效果打折扣的点 · Android

对照物：iOS 对译（`realtimeTranslatorOptimize`），SpeechAnalyzer 双路 + Translation.framework + AVSpeechSynthesizer + 可选 Apple 智能。本节写 **Android 版相对它会差在哪、界面上如何诚实**。不把折扣藏进「后续优化」。

---

## 1. 总表

| 能力 | iOS 对译 | Android v1 | 用户能感觉到 |
| --- | --- | --- | --- |
| 面对面双人插话 | 两路并行，语种路由 | 单引擎多语种切换 | 抢话、连说换语言时丢半句或打错屏 |
| 远场听写 | Analyzer 按会议训练 | OEM 识别器，桌面 40–80 cm 无保证 | 咖啡馆对面声更差，需要更靠近手机 |
| 离线听写六语 | 系统模型，能力可探测 | 视 GMS / 语言包；泰越常缺 | 部分 Chip 灰掉 |
| 离线翻译六语 | 系统翻译包，常已存在 | ML Kit 要再下包 | 首次多等一次下载 |
| 翻译质量 | 系统翻译 | ML Kit NMT | 口语、专名、日语敬语更糙 |
| 同传耳口差 | 从句 TTS，队列 2 | 同策略，TTS 引擎更碎 | 韵律差、偶发抢麦 |
| 会后总结 | Apple 智能，13 明确没有 | Gemini Nano，仅极少旗舰 | 绝大多数机器只有导出 |
| 长时会议 | 流中断可续 | 必须频繁续 `startListening` | 偶发断行，极少需点「继续」 |
| 杀进程恢复 | SwiftData | Room，同语义 | 应对齐，不应差 |
| 后台听写 | 不做 | 不做 | 一致 |
| 无 GMS 手机 | — | **不合格** | 引导失败，请用鸿蒙版或换机 |

---

## 2. 面对面：最大的体验折扣

iOS 规则「识别到的语种 = 路由键」在 Android 上依赖语言检测回调。折扣表现：

1. **误切屏**：一句中英夹杂（「这个 meeting 改到下午」）可能整句打到错误一侧，或中英各闪一次。
2. **丢词**：系统切换语言时官方已知会 drop words。
3. **锁定过死**：用 Android 15 extras 限制切换次数后，对面换语言不会自动跟，必须对调或清屏重来。

产品怎么说：设置里一句小字「两人请轮流说；同时开口时字幕可能跟错。」不要写「和 iPhone 一样准」。

逃生：语言条一键对调（本来就有），误切后用户可对调，不新增「当前说话人」模式。

---

## 3. 听写质量与远场

桌面平放、底部麦克风靠近用户，对面靠远场。Android 识别服务多为近讲助理训练。折扣：

- 对面英文小声、有回响 → 下半屏空白或乱码。
- 噪声下中文相对更稳（国内 ROM），英文掉得更厉害。

缓解只限产品：提示平放中间、调高对方音量；不承诺降噪魔法。v1.1 才评估 sherpa-onnx 远场模型（包体、发热另开）。

---

## 4. 语言覆盖折扣

界面六语都显示。能力灰掉规则：

| 缺什么 | Chip / 开关 |
| --- | --- |
| 听写未安装且无法端侧 | 不可选为「他说的 / 我看的」听写语言 |
| 翻译包没有 | 该方向不可选；可听写但提示「无法翻译，只能出原文」——v1 **不允许**只出原文冒充对译，直接不可选该对 |
| TTS 无声 | 同传读出关且不可开 |

泰国 / 越南用户在 Pixel 上可能齐，在三星上可能缺听写。不要用静态「六语全支持」做商店截图文案。

---

## 5. 同传读出折扣

- Google TTS 中英可用；泰 / 越 / 韩观感不如 Apple 系统声。
- 蓝牙 SCO 导致识别变差时，**优先保字幕、牺牲读出**。
- 禁止外放与 iOS 相同，不打折。不能外放就不要用「小声外放试试」。

耳口差目标仍是 2–4 秒。Android TTS 起读可能更慢，队列仍上限 2，宁可丢旧句。

---

## 6. 会议记录折扣

- 无说话人分离（与 iOS 相同，不是折扣）。
- 续会话可能把一句拆成两行：Assembler 尽量粘，失败则接受「偶发断句」，不在 UI 造假成一句。
- 全文 2 万字上限相同。
- 现场不翻译（与 iOS v1 相同）。

---

## 7. 总结折扣

对绝大多数 Android 用户，总结页只有诚实说明 + 导出。这不是 bug。商店页把「总结」写成「支持 Gemini」会误导——应写成「部分设备可本机摘要，其余可导出到其他工具」。

即使 Nano 可用：输出是要点列表风格，不像 Apple 智能的段落摘要。脚注写清模型名。

---

## 8. 延迟手感

iOS volatile + TranslationSession lowLatency，字幕几乎贴着口型。Android 部分结果频率和 ML Kit 首包更慢，目标：

| 阶段 | 目标 | 可接受折扣 |
| --- | --- | --- |
| 首字上屏 | < 400 ms | 中端机 < 800 ms |
| 译文跟上 | < 700 ms | < 1.2 s |
| final 覆盖 | 立刻 | 同 |

超预算先停 volatile 翻译，只译 final。实时感变差，但比错译乱跳好。

---

## 9. 发热与续航

双路 Analyzer 在 iPhone 上按 45 分钟设计。Android 单路按理更省，但 OEM 识别 + ML Kit 可能唤醒 DSP 不对称。连续 45 分钟同传：中端机可能过热降频，字幕变慢。提示「过热请暂停」，不要暗中降识别质量而不说明。

---

## 10. 明确不打折的点（必须对齐 iOS）

下列若打折，算产品错误，不算平台限制：

- 任务必须显式开始 / 结束，不点新任务不能听  
- 暂停 ≠ 结束  
- 杀进程能恢复未结束任务  
- 不存录音、不上云、不账号  
- 无耳机禁止读出  
- 总结对不支持设备不说「请打开」  
- 分享走系统面板，不深链  
- 倒字用整块旋转，不镜像字形  
- 竖屏锁定  

这些在测试清单里是 P0，与识别准不准无关。
